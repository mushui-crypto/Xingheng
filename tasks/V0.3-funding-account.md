# V0.3 统一资金账户模块任务文档

本文档是 V0.3 的唯一任务源。执行对话不要重复拆小任务；按本文档一次完成端到端闭环。

## 1. 模块目标

将当前“单一模拟交易账户”升级为：

```text
资金账户 Funding Account
交易账户 Trading Account
统一资金流水 Ledger
提现申请 Withdrawal Request
```

V0.3 只做内部账本和流程，不接真实链上、不监听测试网、不发链上交易。

资金单位固定为：

```text
USDT
```

## 2. 不做范围

- 不做真实主网。
- 不做测试网监听。

## 3. 账户模型

### 3.1 资金账户

用途：充值、提现、内部转账、未来链上钱包承接。

字段：

```text
id
userId
asset: USDT
balance
frozen
available = balance - frozen
createdAt
updatedAt
```

规则：

- 后台手动充值进入资金账户。
- 提现只能从资金账户发起。
- 提现申请创建后冻结资金账户金额。
- 内部转账从资金账户转入交易账户时扣资金账户可用余额。

### 3.2 交易账户

用途：下单、持仓、保证金、浮动盈亏。

字段沿用当前交易账户能力，并统一资产为 `USDT`：

```text
id
userId
asset: USDT
balance
equity
usedMargin
freeMargin
floatingPnl
createdAt
updatedAt
```

规则：

- 用户交易只使用交易账户。
- 资金账户转交易账户后，交易账户余额增加。
- 交易账户转资金账户时，金额不能超过 `freeMargin`。

## 4. 资金流水模型

新增统一资金流水，不再把 `balance_adjustments` 作为主流水。

建议表名：

```text
funding_ledger
```

字段：

```text
id
userId
accountId
accountType: funding | trading
type: deposit | withdrawal_freeze | withdrawal_approved | withdrawal_rejected | transfer_in | transfer_out | adjustment
source: admin_manual | withdrawal_request | internal_transfer | onchain_reserved
asset: USDT
amount
balanceBefore
balanceAfter
frozenBefore
frozenAfter
status: pending | completed | rejected
relatedId
network
walletAddress
txHash
remark
createdAt
updatedAt
```

链上预留字段：

```text
network
walletAddress
txHash
```

V0.3 中这些字段可以为空。

## 5. 提现申请模型

建议表名：

```text
withdrawal_requests
```

字段：

```text
id
userId
asset: USDT
amount
status: pending | approved | rejected
network
walletAddress
txHash
remark
reviewNote
createdAt
reviewedAt
updatedAt
```

流程：

```text
用户提交提现申请
→ 校验资金账户 available 足够
→ funding.frozen += amount
→ 生成 withdrawal_freeze 流水
→ 后台审核
```

审核通过：

```text
funding.balance -= amount
funding.frozen -= amount
withdrawal.status = approved
生成 withdrawal_approved 流水
```

审核拒绝：

```text
funding.frozen -= amount
withdrawal.status = rejected
生成 withdrawal_rejected 流水
```

## 6. 接口契约

所有接口返回错误格式统一：

```json
{ "message": "错误原因" }
```

### 6.1 用户侧接口

```text
GET /api/wallet/accounts
```

返回当前用户资金账户和交易账户：

```json
{
  "funding": {
    "id": "FUND-demo-user",
    "userId": "demo-user",
    "asset": "USDT",
    "balance": 10000,
    "frozen": 0,
    "available": 10000,
    "createdAt": 0,
    "updatedAt": 0
  },
  "trading": {
    "id": "ACC-demo-user",
    "userId": "demo-user",
    "asset": "USDT",
    "balance": 1000,
    "equity": 1000,
    "usedMargin": 0,
    "freeMargin": 1000,
    "floatingPnl": 0,
    "createdAt": 0,
    "updatedAt": 0
  }
}
```

```text
GET /api/wallet/ledger
```

返回当前用户流水，按时间倒序。

```text
POST /api/wallet/transfer
```

请求：

```json
{
  "from": "funding",
  "to": "trading",
  "amount": 100,
  "remark": "transfer to trade"
}
```

规则：

- `funding -> trading` 不能超过 funding.available。
- `trading -> funding` 不能超过 trading.freeMargin。
- 成功后生成双边流水。

```text
POST /api/wallet/withdrawals
```

请求：

```json
{
  "amount": 100,
  "network": "reserved",
  "walletAddress": "reserved",
  "remark": "test withdrawal"
}
```

返回提现申请。

```text
GET /api/wallet/withdrawals
```

返回当前用户提现申请。

### 6.2 后台接口

```text
GET /api/admin/wallet/accounts
GET /api/admin/wallet/ledger
GET /api/admin/wallet/withdrawals
```

后台返回全量数据。

```text
POST /api/admin/wallet/deposit
```

请求：

```json
{
  "userId": "demo-user",
  "amount": 1000,
  "remark": "admin deposit"
}
```

规则：

- 充值进入资金账户。
- 生成 `deposit` 流水，source 为 `admin_manual`。

```text
POST /api/admin/wallet/withdrawals/:id/approve
POST /api/admin/wallet/withdrawals/:id/reject
```

请求：

```json
{
  "reviewNote": "approved"
}
```

规则：

- 只能审核 `pending` 状态。
- 审核动作必须生成流水。

## 9. 测试验收

必须通过：

```text
npm run build
```

接口验收：

- 后台给 `demo-user` 充值 1000 USDT，资金账户余额增加。
- 用户从资金账户转 500 USDT 到交易账户，两个账户余额正确。
- 用户从交易账户转 100 USDT 回资金账户，不能超过 freeMargin。
- 用户提交提现 100 USDT，资金账户 frozen 增加，available 减少。
- 后台拒绝提现，frozen 释放，余额不变。
- 用户再次提交提现 100 USDT，后台通过，balance 和 frozen 同时减少。
- 所有动作都有统一流水。
- 服务重启后账户、提现申请、流水仍存在。
- 后台能看到全量账户、全量提现申请、全量流水。
- 用户只能看到自己的账户、提现申请和流水。

## 11. 名词解释

资金账户 = 用户的钱包账本，用来充值、提现、内部转账。

交易账户 = 用户下单用的账户，和保证金、持仓相关。

冻结金额 = 提现审核期间暂时锁住的钱。

Free Margin = 交易账户扣除持仓占用后，还能安全转出的可用资金。

txHash = 链上交易编号。V0.3 只预留字段，不真正生成。

接口契约 = 前后端约定好的请求、返回字段和错误格式。
